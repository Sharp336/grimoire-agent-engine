# Plan 01-02: Observability Wiring

<objective>
Ensure every bounding decision is observable by enriching TransformMetadata and TurnDecision types with exclusion reasons, adding structured logger.debug() calls in captureEffectivePromptSnapshot, and wiring the snapshot to include transform metadata. This is independent of config cutover (Plan 01) and can run in parallel.

Purpose: Operators must be able to see why turns were kept/stubbed/excluded without reading source code. Debug logs must capture the full decision chain.
Output: Enriched types, logger.debug calls in snapshot capture, test proving observability.
</objective>

<must_haves>
- `TurnDecision` type includes `reason` field explaining why a turn was kept, stubbed, or excluded
- `TransformMetadata` includes aggregate counts: `keptCount`, `stubbedCount`, `excludedCount`, `totalInputTokens`, `totalOutputTokens`
- `captureEffectivePromptSnapshot()` emits `logger.debug("context-assembler:snapshot", ...)` with structured metadata
- `EffectivePromptSnapshot` type includes bounding-related fields (transform metadata or summary thereof)
- Tests verify that snapshot capture includes expected bounding decision data
- `bun check` passes
</must_haves>

<action>
In `packages/coding-agent/src/context/assembler/types.ts`:

**Step A: Enrich TurnDecision**

Add a `reason` field to the `TurnDecision` interface:
```typescript
reason: string; // e.g. "hot-window", "budget-fit", "stubbed-over-budget", "excluded-tool-transcript"
```

Also add an `action` field if not already present:
```typescript
action: "keep" | "stub" | "exclude";
```

And add token-level detail:
```typescript
inputTokens: number;   // tokens this turn consumed in input
outputTokens: number;  // tokens this turn consumed in output (0 for user turns)
```

**Step B: Enrich TransformMetadata**

Add aggregate summary fields to `TransformMetadata`:
```typescript
keptCount: number;
stubbedCount: number;
excludedCount: number;
totalInputTokens: number;
totalOutputTokens: number;
budgetUsedTokens: number;
budgetMaxTokens: number;
```

These fields summarize the full transform pass for easy logging.

**Important:** Check the existing field names in both interfaces. Do NOT duplicate existing fields. If a field already exists with a different name, keep the existing name and add only the missing fields. Add fields as required (not optional) since every transform pass should populate them.
</action>


Import `TransformMetadata` from `./assembler/types.ts`. Use the correct relative import path based on the file's location in `packages/coding-agent/src/context/`.

**Step B: Update captureEffectivePromptSnapshot**

Modify `captureEffectivePromptSnapshot()` to:
1. Accept `TransformMetadata` as an optional parameter (or read it from the result object it already receives — check the function signature).
2. Store it on the returned `EffectivePromptSnapshot` object.
3. Add a `logger.debug` call that emits the bounding decision summary:

```typescript
import { logger } from "@oh-my-pi/pi-utils";

// Inside captureEffectivePromptSnapshot, after building the snapshot:
if (snapshot.transformMetadata) {
  const meta = snapshot.transformMetadata;
  logger.debug("context-assembler:snapshot", {
    kept: meta.keptCount,
    stubbed: meta.stubbedCount,
    excluded: meta.excludedCount,
    budgetUsed: meta.budgetUsedTokens,
    budgetMax: meta.budgetMaxTokens,
    totalInputTokens: meta.totalInputTokens,
    totalOutputTokens: meta.totalOutputTokens,
  });
}
```

**Step C: Check logger import**

Verify `logger` is imported from `@oh-my-pi/pi-utils`. If not already imported, add the import. Do NOT use `console.log` per AGENTS.md rules.
</action>
