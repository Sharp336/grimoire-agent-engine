# Changelog

## [Unreleased]

### Added

- Initial release: session-quota-aware prompt queue (`/scheduler`) — queue prompts and drain them unattended across Claude 5-hour session windows, with provider rate-limit holds (429 retry-after), network-outage backoff probing, a self-healing watchdog, pause-on-user-abort, resume-not-skip semantics, crash recovery, and `/scheduler export`.
- `/scheduler add-file` batch format: a file of comma-separated `{prompt: "..."}` objects (whitespace/newline tolerant, bare or quoted keys, optional `[...]`, trailing comma ok) queues up to 30 tasks atomically; syntax/shape errors queue nothing and name the offending entry. Plain-text files still queue as one prompt.
- `/scheduler add-file` verbatim batch format: a file starting with an `@@prompts` header splits into prompts on `---` separator lines and takes each prompt body **exactly as written** — no escaping of quotes, back/forward slashes, newlines, JSON, or pasted code. Pick a custom boundary with `@@prompts sep=<token>` (heredoc/MIME-boundary style) when prompts contain the default separator. Leading/trailing/doubled separators are ignored; still capped at 30 and queued atomically. The legacy JSON `{prompt: "..."}` batch remains supported as a fallback, and files without a header still queue as one prompt.
- Content-policy ("cyber") violation recovery: when a turn is rejected by Anthropic's usage-policy classifier, the poisoned conversation is purged with a fresh context (`ctx.newSession`, `compact` fallback) before the task is re-dispatched with the resume preamble, and the attempt is refunded so a poison cascade never burns the `maxAttempts` budget. A new `maxContextResets` config (default 5) fails a prompt that trips the classifier even in a clean context instead of looping forever. Logged as a `context_reset` event.
- Self-describing diagnostic logging: every `end` record now carries the turn `classification` (`rate_limit` / `outage` / `content_policy` / `user_abort` / `task_fault` / `stalled` / `shutdown`), whether the attempt was `refunded` vs counted, the `attempts`/`maxAttempts` budget, a `terminal` flag with the exact `/scheduler retry <id>` recovery hint, and a truncated `prompt`. `dispatch` records carry the prompt and attempt budget too. `/scheduler log` renders these inline (e.g. `end t2 failed task_fault counted attempts=3/3 TERMINAL » …`), so "why did it fail and will it retry?" is answerable from the log alone — no opening `state.json` or reading the source classifiers.
- Prompt-hash tracking + outcome ledger: every task carries a stable `promptHash` (SHA-256/12 of the prompt, backfilled for existing tasks) so the same prompt is traceable across runs and re-queues. After every pass/fail the scheduler regenerates a human-readable table at `task-ledger.md` — `hash | status | prompt (≤100) | summary (≤100)` — where the summary is generated purely by code (the turn's own final assistant line for a pass, or `classification: error` otherwise), never an extra LLM call. View it with `/scheduler ledger`; `promptHash` and `summary` are also stamped on `end` log records.

### Fixed

- Background timers (dispatch, resume, and the watchdog) now schedule through the managed extension-context timer surface instead of raw globals, so a throw inside a timer tick — e.g. an I/O error while persisting `state.json`/logs from a dispatch — is contained and reported through the extension error channel instead of escaping as a process-fatal `uncaughtException` that could tear down the omp session.
- `/scheduler start` approval-mode preflight now also inspects `config.yaml`, not just `config.yml`, matching the filenames the core settings loader accepts — a non-`yolo` `tools.approvalMode` persisted in `config.yaml` is no longer missed by the overnight-stall warning.
- Non-terminal `agent_end` events (`willContinue: true` — auto-retry, unexpected-stop retry, auto-compaction continuation) no longer settle the in-flight task or dispatch the next one. The scheduler now waits for the final `agent_end`, so a continuation can't double-run (settle + fire the next task while the same turn is still resuming).
- Provider retry-exhaustion is now read from the `auto_retry_end` event's real `finalError` field (previously `error`, which is never populated). Outages/timeouts/5xx are again classified as outages (exponential backoff) instead of collapsing into the generic "rate limit" string, and a provider `retry-after-ms` is honored as the exact hold instead of defaulting to a one-hour wait.
- Content-policy context purge now sources `newSession` from the retained command context. The host exposes `newSession` only on the command context (`createCommandContext`), never the event/timer context the autonomous purge runs from, so the previous code always fell back to `compact` (which re-summarizes the poisoned transcript and can re-trip the classifier). The true no-LLM `newSession` purge now runs whenever a `/scheduler` command has been issued in the session.
- Default quota profile is anchored to the Anthropic **provider** (`match: "^anthropic$"`) so it can't match a bare model id — a third-party catalog serving a `claude`/`anthropic.*` model under another provider (Bedrock, OpenRouter, API-key gateways) falls through to the unlimited `.*` profile and dispatches ungated instead of inheriting the 5h×4 subscription window.
- A cancelled `newSession()` (a hook vetoes the `session_before_switch`) is no longer logged as a successful purge. The scheduler checks the returned `{ cancelled }` state and, when the session was not switched, falls back to `compact` or keeps the reset pending — so a content-policy task is never re-dispatched into the still-poisoned transcript on the mistaken belief the context was cleared.
- Data dir, state, and the approval-mode preflight now resolve through the shared `getAgentDir()` resolver, so `PI_CONFIG_DIR`, named profiles, and the XDG layout are honored exactly as omp's own config loader does (previously only `PI_CODING_AGENT_DIR` was, so a `PI_CONFIG_DIR` install read/wrote the wrong tree and could miss a persisted non-`yolo` approval mode).
- Transient provider failures no longer leave phantom session windows. `agent_start` optimistically records a window for gated profiles; when the turn then fails as an outage or rate-limit rejection (which refund the attempt), the just-recorded window is now dropped too — a long outage can no longer accrue windows that eventually trip the rolling-24h quota cap even though no Claude session was ever opened.
- Output-truncated terminal turns (`stopReason` `length`/`max_tokens`/`incomplete` the core could not auto-continue) are now treated as interruptions instead of successes. Previously any last assistant message that was not `error`/`aborted` marked the task `done`, so an unattended run could record incomplete work as finished; such turns now resume with the resume preamble (or fail visibly after `maxAttempts`).
- A prompt-delivery failure (`sendUserMessage` throwing before the turn starts, e.g. a host mode that rejects prompt flow) now respects `maxAttempts` instead of re-dispatching every 30s forever: it fails the task once the attempt budget is exhausted, with the terminal `end` log and `/scheduler retry` hint.
- Corrupt `config.json`/`state.json` are preserved instead of silently replaced. `readJson` distinguishes a genuinely missing file (ENOENT) from a parse/IO error, and a syntactically-valid but structurally-invalid state file (e.g. `{}` missing `tasks`/`run`/`nextTaskSeq`, or a `tasks` array with malformed rows lacking `id`/`prompt`) is treated as unreadable too instead of being coerced into an empty queue or crashing while backfilling. A malformed config is left untouched (defaults used for the session) and a bad state file blocks saves rather than being overwritten. While the state file is unreadable, mutating `/scheduler` commands (`add`, `start`, `remove`, …) are refused rather than accepted in memory only and lost on restart; the scheduler resumes automatically once the file is fixed or deleted (no restart needed).
- `/scheduler retry` now clears a failed task's `policyResets` alongside its attempt budget, so a task that failed after exhausting `maxContextResets` gets a fresh content-policy reset budget on retry instead of failing on its next flagged turn.
- A dispatched turn that never materializes (no `agent_start` — an undeliverable prompt from no model/API key, a rejecting pre-turn hook, or a `sendUserMessage` that rejects asynchronously) is now failed after `maxAttempts` consecutive watchdog stalls instead of being re-queued on refunded attempts forever. A turn actually starting resets the per-task stall counter, so a one-off swallowed message still recovers transparently. `/scheduler retry` clears the counter too.
- `/scheduler` now emits a one-shot notice when it applies a gated (session-window) quota profile, spelling out that this assumes Claude **subscription** auth and that API-key/pay-as-you-go billing should set the profile's limits to `null` to run ungated. The extension cannot see credential kind through the documented model API, so a gated default is a subscription assumption made visible rather than silent.
- The approval-mode preflight parses config YAML with a real parser (`Bun.YAML`) instead of a single-line regex, so a flow-style `tools: { approvalMode: … }` map (which the core loader accepts) is detected and the non-`yolo` overnight-stall warning fires correctly. It also scans the project files every settings provider merges verbatim — `.omp/config.*`, `.claude/settings*.json`, `.cursor`/`.gemini` `settings.json`, `opencode.json`, and `.codex/config.toml` (TOML via `Bun.TOML`) — warns whenever **any** layer is non-`yolo` (it can't see the host's merge precedence, so it never masks a non-`yolo` layer behind an earlier `yolo` one), and additionally flags a non-`allow` per-tool `tools.approval.<tool>` policy, which the core honors in every mode so it can block an unattended run even under `yolo`.
- Widened the `@oh-my-pi/pi-coding-agent` peer range to `^16 || ^17` so installing the extension alongside current omp (17.x) doesn't trip strict peer resolution.
- State/config validation is now full-shape. `migrateState` rejects a `state.json` whose `run` isn't a valid mode, `nextTaskSeq` isn't a finite number, a task row is missing/mistypes a required `SchedulerTask` field (`id`/`prompt`/`status`-enum/`addedAt`/`attempts`) or a present optional, or a window row is neither a legacy ISO string nor `{startedAt, profile}`. `loadConfig` rejects a `config.json` with any wrong-typed field (e.g. `promptPreamble: 123`, a non-numeric delay, a malformed `quotaProfiles`), falling back to defaults for the session without overwriting. All route through the existing preserve-and-refuse safe path rather than being coerced (which previously hid rows from status filters or crashed string/number helpers).
